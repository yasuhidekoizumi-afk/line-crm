# LINE一斉配信画面 次期アップデート設計（/broadcasts v2）

最終更新: 2026-11-15 / 対象: `apps/web/src/app/broadcasts/page.tsx`, `apps/worker/src/routes/broadcasts.ts`, `apps/worker/src/services/broadcast.ts`

## 0. 結論

今の画面は「作って送る」はできるが、**「何人が届いたかを正しく記録し、次の配信判断に使う」ができていない**。
本番実測で、全員配信8件はすべて「成功 0 / 0 件」で記録され、ブロック率は77件中59件が計算不能（最大47,700%）、
送信済み92件のうち開封率が出るのは11件だけだった。数字が嘘をついている状態を先に止める。

着手順は **A → B → C**（DはAと並行可）。

| 記号 | 内容 | 根拠（本番実測） | 順 |
|---|---|---|---|
| A | 実績の記録を正す（全員配信の件数・ブロック率・開封率の分母） | 全員配信8件が成功0名 / ブロック率59件が計算不能 / 開封率は11/92件 | 1 |
| B | 誤送信を防ぐ（1名テスト送信・送信前チェック・複製の警告） | テスト配信は「宛先は本番と同じ」フラグのみ | 2 |
| C | 配信→売上（クリック→注文・売上・貢献利益） | クリック数までしか出ない | 3 |
| D | 運用（一覧の検索・期間・ページング・CSV・失敗分の再送） | 全件読み込み・失敗配信は再送不可 | 並行 |

## 1. 本番実測（2026-11-15、D1 `--remote` 直接集計）

| 指標 | 実測値 |
|---|---|
| `broadcasts` 状態 | sent 92 / draft 2 / scheduled 1 |
| 宛先種別（全体 / 送信済み） | segment 50/48、tag 29/29、all 9/8、individual 7/7 |
| 全員配信（`target_type='all'`） | 8件すべて `success_count=0`・`total_count=0`・`messages_log` 0行・集計単位なし |
| 全体配信のクリック実績（同じ8件） | 11/2: 114タップ（識別64人） / 11/4: 142（89人） / 11/10: 206（142人） |
| ブロック率が入っている配信 | 77件。うち `unfollow_count_at_send` が NULL 59件、負値 6件、最大 47,700%、最小 -50% |
| 開封率が取れる配信 | 11件（すべて segment、集計単位の導入 2026-09-14 以降） |
| `messages_log` が0行の送信済み | 全員配信 8件 + 7/1の大規模配信3件（259名・129名・4名）+ 小規模10件。**7月以降の通常配信では0件** |
| 月次配信量 | 9月 19配信・17,494通 / 10月 1配信・2,644通 / 11月 7配信・5,707通 |

読み取れること:

1. **全員配信は「届いていない」ように見える。** LINEの全員配信APIは宛先数を返さないため `success_count=0` で保存され
   （`apps/worker/src/services/broadcast.ts:336-347`）、画面は「成功 0 / 0 件」と表示する（`page.tsx:1086-1092`）。
   一方で同じ配信に142人・89人・64人のクリックが付いており、実際には届いている。**画面の数字が事実と逆**。
2. **ブロック率は式が成立していない。** 送信時スナップショット（`unfollow_count_at_send`）が59件でNULLのままなので、
   累積unfollow数がそのまま分子になり、1名配信が47,700%になる（`services/broadcast-block-metrics.ts`）。
   そもそも画面には未表示で、計算だけが毎時走っている。
3. **開封率は12%の配信しか出ない。** 計測は配信ごとの集計単位（`line_aggregation_unit`）が必要で、導入が9/14のため
   過去分は復元できない。tag配信は導入後に1件も送っていないため未検証（最後のtag配信は9/3）。
4. **失敗した配信は再送できない。** 429で全滅した配信（7/25「新フレーバー販売開始予告」）は `status='sent'` のため
   reset が拒否される（`routes/broadcasts.ts:990-992`）。複製して作り直すしかない。

## 2. A: 実績の記録を正す（Phase 1）

### A-1 全員配信の件数とログ

- **送信時に `countBroadcastTargets('all')` の結果を `total_count` に入れる**（`routes/broadcasts.ts:48-62` に実装済みの集計を使う）。
  値は「送信時点の友だち数（推定）」とラベルする。LINE側の実配信数とはブロック・退会分だけズレるため、断定しない。
- 個別ログ（`messages_log`）は全員配信では作らない。代わりに詳細画面で「全員配信（個別の送信控えなし）」と明示し、
  クリック率・開封率の分母は `total_count` にフォールバックする。
- 失敗時は `failed_count` に理由を残す（現在は0件扱いで、成功と区別できない）。

### A-2 ブロック率

- 送信時に `unfollow_count_at_send` を必ず記録する（現在はNULLが59件）。
- スナップショットが無い配信は**率を出さない**（NULLのまま）。負値は0として扱わず、非表示にする。
- 表示するなら詳細画面に「24時間ブロック率」として出し、テスト配信・individual配信は除外する。
- 表示しない方針なら、毎時cronの計算（`computeBroadcastUnfollowRates`）ごと止める。今は計算だけが走って誰も見ていない。

### A-3 開封率・CTA率の分母

- 現在の分母は `deliveredCount`（公式統計の delivered か `success_count`）。全員配信は両方0のため率が `null` になる
  （`routes/broadcasts.ts:562-580`）。`total_count` を最終フォールバックにする。
- 「20人未満は非表示」は維持（LINE公式の仕様）。

### A-4 失敗配信の復旧

- 失敗（`failed_count>0` かつ `success_count=0`）の配信は「下書きに戻す」を許可する。現在は `sent` を一律拒否している。
- 部分失敗（一部バッチだけ失敗）は、失敗した受信者だけ再送できるようにする。`broadcast_recipient_sends` に成功分が
  残っているので、差分送信が可能。まずは全滅ケースの復旧から。

## 3. B: 誤送信を防ぐ（Phase 2）

### B-1 1名テスト送信

- 現状の「テスト配信」チェックは**同日重複除外をしないフラグ**にすぎず、宛先は本番と同じ（`broadcast-form.tsx:271-282`）。
  テストのつもりで全員に送る事故が起きる構造。
- `POST /api/broadcasts/:id/test-send { lineUserId }` を追加し、フォームに「自分にテスト送信」を置く。
  履歴には `is_test=1` で残し、一覧の「テスト」タブに出さない（本番集計と混ぜない）。

### B-2 送信前チェック

- URLの疎通（200/30x、リダイレクト先の存在）、LINE1通あたりの文字数、画像のサイズ・形式。
- NGワード（医薬品的な効能表現・景表法）の検出。現状は文章をそのまま送れる。
- 配信対象0名の警告（全員配信で `countBroadcastTargets` が0のとき）。
- 直近配信のブロック率が閾値（例: 1.5%）を超えていたら警告を出す。

### B-3 複製の警告

- 11/10の配信はタイトルに「（コピー）」が残ったまま送信され、同名の下書きが2件残っている。
  「同じ本文を過去30日に送信済み」の警告を複製時に出す。

## 4. C: 配信→売上（Phase 3）

- 現状はクリック数まで。注文・売上・AOV・貢献利益は配信単位で出ないため、月5〜6配信・1.7万通の投資判断ができない。
- 実装は既存部品の再利用で足りる: `tracked_links` / `link_clicks` → `shopify_orders` / `shopify_order_items`
  （「クリックしたが買っていない人」抽出と同じ結合。`references/click-tracking-and-nonbuyer-segments.md`）。
- 配信詳細に「クリック→7日以内の注文」を集計し、注文数・売上・AOV・貢献利益・配信1通あたり売上を表示する。
- 分母は配信成功数（全員配信は `total_count`）。率だけでなく金額を出す。

## 5. D: 運用（Phase 1と並行）

- 一覧は全92件を一括読み込み。検索・期間・宛先種別・ステータスの絞り込みとページング、CSV出力を追加する。
- 失敗理由の行内展開は実装済み。失敗の再送（A-4）とセットで導線を作る。

## 7. リスク

- 全員配信の件数を友だち実数で埋めると、LINE側の実配信数と数%ズレる。**「推定」と明示**して断定しない。
- ブロック率の過去59件は復元できない。過去分は「計測なし」として扱い、遡って埋めない。
- 開封率は集計単位の導入前（92件中81件）は永久に出ない。比較したい場合は9/14以降の配信だけで見る。
- 全員配信はLINE側でブロック者を除外するため、`total_count` と `success_count` の意味が tag/segment と異なる。
  画面のラベルを「配信（推定）」に統一しないと、また誤読が起きる。
