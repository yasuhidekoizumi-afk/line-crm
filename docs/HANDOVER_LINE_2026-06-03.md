## 1. 当初の理解 → 実際に判明した構造（3層の問題）

「配信0件だから第1回配信を出そう」で始めたが、調査で根の深い問題が判明：

1. **機能重複** — LINE公式Manager と line-harness で配信・ステップ・タグが二重化。役割分担が未定義だった。
2. **データ破損** — 2026-04-09の一括インポートで Harness DB が壊れている。
   - メインアカ `@055dpflo` の友だち：公式 **15,126人** / Harness **6,829人**しか把握せず（実数の半分以下）。
   - `isFollowing=false` がoffset連続の塊で約半数 → 自然なブロックでなくインポートバグ。
   - `friends/count` はisFollowing未除外 → 「20,134」は累計総数で無意味。
3. **配信0件の真因 = 通数上限ではなく「今月一度も配信していないだけ」**（`messagesThisMonth: 0`）。箱はある、動かせば飛ぶ。

その他の発見：
- 公式LINEアカウントは**2つ**（`@055dpflo` メインD2C / `@603dsbmv` 楽天店・友だち12人）。
- Harness配信は multicast/push（`apps/worker/src/services/broadcast.ts`）＝公式の通数枠を消費。「Harnessに寄せれば上限回避」は**不成立**。
- 既存テスト配信に『アサイーハワイアン』の完成度高いFlex原稿あり（broadcastId 71ddb512…、商品URL oryzae.shop/products/acai-hawaii）。第1回配信の叩き台に流用可。

## 2. 確定した方針

**公式 = 配信実行 / Harness = 頭脳（ポイント・CRM・名寄せ・自動化）。**
マス配信は公式+人間、精密配信（失効前ポイント償還等）だけ将来 Harness+AI へ**段階的に**移行。
- AI自動化の価値は「全部自動送信」でなく「人手では回らない精密配信の自動化」。
- 失効前償還（移行Phase3本命）は現APIに無く（`loyalty/expiring`=404）Worker拡張＝🔴要承認。
